## 現状

Article / Tune / Album の3集約で domain → application → REST → 統合テストの Create/Get/Update/Delete/List が通っている。Album のトラック、アセット（画像）アップロード、認証・認可、公開/非公開制御も実装済み。Tune の CRUD と、トラック上のテキストによるチューン構成は別で、既存 Tune を選んで紐付ける操作は持たない。記事は種別ごとのサブタイプに分かれ、アルバムへの参照を持てるのは `AlbumArticle`（`ALBUM` 種別）のみ。サイトの文言（`SiteContent`）はキーで引く形で持ち、登録・更新と全件照会だけを備える（削除の経路は持たない）。公開サイト（`frontend-public`）は一覧・詳細・トップ・404 を持つ（#123）。

管理画面（`frontend-admin`）は作品・記事の一覧・公開・非公開・削除・追加・編集と、サイトの文言の一覧・編集を持つ。作品では本体の項目、カバー画像、外部音源、トラック・テキストのチューン構成を編集でき、記事では本文・タグ・作品参照を扱う。作品・記事の一覧はページ送りを備える。ブラウザは元のAPIキーを交換にだけ使い、期限付きセッションを保持する。作品一覧は通信期限・結果不明時の再照会・実際の影響記事の表示を持つ。作品・記事の編集にはタブ内の入力復旧があり、本文のMarkdown入力支援と外部音源の登録前プレビューも利用できる。復旧と通信失敗の保証範囲は [管理画面の説明](../frontend-admin/README.md) を正とする。

作品の子を書く経路は集約ルートに1つで、外部音源の追加・取り外し・並べ替えはどれも入力の操作として作品の保存に乗る（#391）。並びは送った配列の位置がそのまま表し、番号は要求が運ばない。トラックとチューン構成は追加・取り外し・並べ替えを編集でき、保存後の読み直しまで実スタック E2E が通る。文言のキーは画面が閉じず、公開サイトが読むキーを候補として出すだけで、そこに無いキーも足せる。

作品は頒布の基準額を1つ持ち、作品紹介の記事にだけ出る。作品は原作の出典も1項目持つ——人が書いた一文で、構造化せず、トラック側には置き場を作らない（DECISIONS 6）。

マークアップの描画は `packages/markup` が担う（Markdown からサニタイズ済み HTML への変換。公開サイトと管理画面のプレビューが同じ関数を呼ぶ）。

見た目は配色と書体の実値までトークンに入っている（DECISIONS 25）。公開サイトは外部から書体を読み込み、届くまで画面を覆う。サイトの印は公開サイトが持ち、リンクプレビューの既定画像はその印から組み立てのたびに焼く——どのページも、作品から採る画像が無ければこの既定になる。印は既定であって正式な意匠ではない（正式版は運用側で決める。#375）。管理画面は印を持たない。ページの末尾はコピーライト表示だけを持ち、主体はデータ側、年と記号は画面が組み立てる（静的出力のため、年は次に作り直すまで変わらない）。ページ送りは、たどれない側を出さずに場所だけ空ける。作品と記事は、本文の左に立つ印で見分ける——横倒しの斜体の文言（`Work` / `Article`）を、その下線になる縦の罫が受ける。罫は本文の端から端まで通り、文言は見出しの分を空けてから始まって罫に触れる。書体は斜体の実体を持たないため、描かれるのは処理系が傾けた合成の斜体。置くのはページだけで、一覧のカードには置かない。これは**ページの種類**で、記事の種別（作品紹介・ノートほか）は画面に出さない（#346）。

E2E（Playwright）は実スタックに対して公開サイト・管理画面の両方を通し、同じ実行からレビュー証跡を出す（#164）。証跡は `evidence` 孤立ブランチへ PR ごとに置く。

試聴機能は公開・管理画面から独立した PoC として存在する。保存済みManifest・shell・音源によるオフライン再生と、AudioWorkletの特徴量によるVisualizerの駆動を接続している。合成音源とブラウザ検査による確認は、実音源・対象端末での可聴出力や長時間動作、本番の配布・準備の受け入れを意味しない。

経路・担い手・地域に紐づく頒布情報・入手経路の実体は実装を持たない（作品が持つのは基準額まで）。帰属が（作品 × 発表）であり、発表を第一級の概念にする設計とセットで作る（#201）。
