# 非公開FLACの受入検査（#474）

## 現在の実装境界

実装済みの境界は、非公開音源の検査器、専用の保存アダプタ、DBの登録状態と、それらを結ぶ確定・復旧処理。
検査器の一時領域管理、登録期限処理、入力読込期限と既定無効の単一実行入口まで接続済み。
管理者向けの登録予約・状態照会・Albumへのクロスフェード関連付けまで実装済み。
FLAC本体のHTTP受信・確定/明示復旧APIまで接続済み。
認証した試聴端末への配布は #475 が担当し、端末の資格情報の発行・失効と端末ロールの認証まで接続済み。
公開画像のアップロードAPIには接続しない。取得URLを返す経路はない。
CDIの実行入口は明示的に有効化したときだけ専用資源を生成する。
管理APIの一部が使えるだけで #474 を完了とはしない。

## 試聴端末の資格情報（#475 A）

端末は管理APIキーを持たない。管理者が端末ごとに期限付きの端末トークンを発行し、端末はそれをBearerで送る。
サーバーはトークンのSHA-256 digestと期限・失効時刻だけを `listening_device` に置き、本体は発行応答で一度だけ返す。
トークンは `abs_device_` 接頭辞で管理セッション（`abs_session_`）と区別し、認証機構が接頭辞で照合先を選ぶ。
期限内かつ未失効の照合はDB時計で行い、一致した要求は `listener` ロールだけを持つ。管理者ロールは持たない。
管理者は端末ロールを持たないため、配布の入口（#475 B以降）は端末だけに開く。

管理APIはすべて `admin` ロールと `abservice.private-audio.enabled` が真であることを要求し、無効時は404。

| 操作 | 契約 |
| --- | --- |
| `POST /api/v1/admin/listening-devices` | `label`（1〜100文字）と任意の `validDays`（1〜90、既定30）。201・相対Location・保存禁止ヘッダで、端末の状態とトークン本体を返す |
| `GET /api/v1/admin/listening-devices` | 発行の新しい順の一覧。状態は ACTIVE / EXPIRED / REVOKED で、トークンやdigestは返さない |
| `DELETE /api/v1/admin/listening-devices/{deviceId}` | 失効。以後の認証は401。失効済みへの再実行は204、未存在は404、不正なIDは400 |

有効期限は利用で延長しない。再認証は新しい発行で行い、古いトークンは期限か失効で使えなくなる。
失効は以後の認証を拒むもので、既に認証され実行中の要求を取り消す機能ではない。
端末側で既に保存した配布物の扱いは #477 が定める。

## 配布パッケージ（#475 B）

`GET /api/v1/listening/package` は `listener` ロールだけに開く。管理者は403、未認証は401、機能無効時は404。
応答は `packages/installation` の schema v3 と同じ項目だけを持つ Manifest で、端末側の厳密な検証がそのまま通る。
応答の形は `packages/installation/fixtures/manifest-v3.example.json` を見本とし、端末側の単体試験と backend の統合試験が同じ見本と照合する。
`ETag` に `packageVersion` を載せ、`Cache-Control: no-store` で中継やブラウザに残さない。

対象は公開済みの作品のうち、CONFIRMED のクロスフェードが関連付いているもの。下書きは含めず、関連付けの無い作品も含めない。
作品・確定音源・収録曲・チューン構成を1つの問い合わせで読み、1つの版の中で実体とメタデータが食い違わないようにする。
作品の並びは公開サイトの作品一覧と同じ（カタログナンバーの降順、未付与は末尾、同値はドメインIDの降順）、収録曲は曲順。

| 項目 | 由来 |
| --- | --- |
| `packageVersion` | `packageVersion` 自身を除く Manifest の内容全体（schema 版・互換範囲・表示素材・音源・作品・曲・再生項目の並びと値）の SHA-256。同じ内容なら同じ値、どれか1つでも変われば別の値。時刻や乱数を含まない |
| `compatibleAppVersion` | `[1,10,0]` 以上 `[2,0,0]` 未満 |
| `albums[]` の表示情報 | canonical な Album の `artistDisplayName`（必須）と、任意の `releaseDate`・`catalogNumber`・`description` と `descriptionFormat`（一組）・`originalWorkNote`。値の無い任意項目はキーごと省き、空文字列は値として載せる。説明文は原文と形式（`PLAIN_TEXT` / `MARKDOWN`）のまま載せ、HTML にしない。本文中の差し込み画像は asset に含めない |
| `albums[].tracks[]` | canonical な Track の ID・曲順・曲名。曲名が無ければ公開サイトと同じ規則でチューン名から組む。音源を要求しない |
| `albums[].artworkAssetId` | カバー画像の assetId（配信キー）。確定時に実測値を記録した画像だけを載せ、無い作品では項目自体を省く（schema は null を拒む） |
| `assets[]` | 音源は登録IDを assetId とし、byteLength・SHA-256 は登録テーブルの確定値で `audio/flac`。表示素材は配信キーを assetId とし、byteLength・SHA-256 は確定時に保管先が計算した値で画像の Content-Type。いずれも `required: true`。同じ実体は1件 |
| `playbackItems[]` | 作品ごとに1件の `album-crossfade`。ID は `album-crossfade:{albumId}` で、音源の差し替えでは変わらない。長さは totalSamples ÷ sampleRate |
| `presentationAssetIds` | 作品の artwork の assetId。作品順で、複数の作品が同じ画像を使っても1件 |

表示素材（artwork）は作品のカバー画像で、確定時に `published_asset` へ記録した実測値を持つものだけを載せる。
記録の無い画像（この記録より前に確定したもの、記録だけが失敗したもの）は、同じキーで `POST /api/v1/assets/{assetKey}/confirm` を送り直すと、コピーをせずに記録だけが補われ、以後の配布パッケージで表示素材になる。
表示素材の実体は公開サイトと同じ配信パス（`/assets/{assetId}`）から取る。署名は要らず、音源の取得URLの経路（下記）では解決しない。

URL・保存キー・資格情報は含めない。音源の取得URLは下記の経路で期限付きに解決する。
関連付けが変わると版が変わり、端末は保存済みの版と比べて更新の要否を判断する。

## 音源の取得URL（#475 C）

`GET /api/v1/listening/package/assets/{assetId}/url` は `listener` ロールだけに開き、現在のパッケージに含まれる音源だけを解決する。
管理者は403、未認証は401、機能無効時は404。形が不正な assetId は400。
公開済み作品の確定クロスフェードとして関連付いていない音源は、未確定・未存在・関連付けが外れたものを区別せず404にする（端末に登録の有無を教えない）。
応答は `assetId`・署名付きの `url`・`expiresAt` で、`Cache-Control: no-store` を付ける。

URLは専用バケットの確定済み実体を指す S3 の署名付き GET で、端末は backend や CloudFront を経由せず S3 から直接取得する。
署名は保存側と同じ資格情報（AWS 標準の provider chain）で行い、公開画像用の署名器と開発用の静的資格情報は流用しない。
有効時間は `abservice.private-audio.download-url-expiry`（既定10分、1分〜1時間）を上限とし、
署名資格情報の残存時間（5秒の余裕込み）と端末の資格情報の期限の短い方へ短縮する。端末の期限は絶対時刻の上限として署名器へ渡し、
署名後にも期限がそれを超えていないことを検査する。超えていれば URL を返さない。`expiresAt` は署名と同じ秒単位の期限。
署名は要求ごとに行い、URLを保存しない。発行済みのURLは期限まで有効で、関連付けの差し替えや非公開化は次の解決を404にするだけで、
既に発行したURLを取り消さない。端末は `packageVersion` の一致で整合を取る（#477）。

ブラウザから S3 へ直接 GET するため、専用バケットの CORS は IaC の `private_audio_download_origins`（既定は空）で
試聴サイトの正確な HTTPS オリジンだけに開く。許すのは GET と `Range` だけで、PUT・ワイルドカード・他オリジンは許さない。
バケットのポリシーと Block Public Access は変えない。

## 管理API（C1/C2）

すべて `admin` ロールを要求し、既存の管理Bearer認証を使う。
実行基盤と同じ `abservice.private-audio.enabled` が厳密な文字列 `true` の場合だけ利用できる。
無効時は管理者でも404、未認証は401、権限不足は403となる。未完成機能の公開停止と認可を別に検査する。
エラーは既存のProblem Details、API型と失敗契約は実装からOpenAPIへ生成する。

| 操作 | 契約 |
| --- | --- |
| `POST /api/v1/admin/private-audio/registrations` | 本文なし。サーバーが音源IDと15分の受付期限を発行し、201・相対Location・PENDING状態を返す |
| `GET /api/v1/admin/private-audio/registrations/{audioId}` | 登録状態・予約日時・期限・検査済みなら実測メタデータを返す。URL・保存キーは返さない |
| `PUT /api/v1/admin/private-audio/registrations/{audioId}/content` | `audio/flac`の生バイト列を送る。期限内のPENDINGのみ受け付け、検査・保存・確定を完了すると200と登録状態を返す |
| `POST /api/v1/admin/private-audio/registrations/{audioId}/confirm` | 本文なし。INSPECTED/ABANDONEDを保存実体と照合して確定復旧する。CONFIRMEDは200で現在の状態を返す |
| `GET /api/v1/admin/albums/{albumId}/listening-audio/crossfade` | Albumのクロスフェード選択と専用revisionを返す。未設定はaudioId=null・revision=0、Album未存在は404 |
| `PUT /api/v1/admin/albums/{albumId}/listening-audio/crossfade` | `audioId`と必須の`expectedRevision`を送る。CONFIRMEDのみ選択でき、成功時に専用revisionを1進める |

不正なID・世代は400、未存在のAlbum・音源は404、未確定音源・古い世代は409。
同じ世代の並行要求は一つだけ成功する。Albumの参照ロックと選択の更新を同一トランザクションで行い、
Album本体の編集世代・公開データ世代・公開APIの表現は変更しない。
Album削除時は選択を除去し、登録記録や保存音源は削除しない。別音源への変更でも旧音源は保持する。

この経路はクロスフェード専用で、応答のkindは`album-crossfade`。Track IDや曲番号を推測して関連付けない。
将来の曲別音源は共通の登録・検査・保存基盤を使い、canonical Trackを検査する別の関連付けとして拡張する。
現時点で曲別の関連付けAPI・Manifest生成・端末配布は提供していない。

予約→FLAC送信→状態照会→Album関連付けの順に操作する。送信成功は検査・保存・DB確定の完了を表す。
不正FLACは400、期限切れ・再送・実行枠の競合・復旧時の実体未存在/不一致は409。
HTTP容量超過は本文を伴わない413になる場合がある。通信障害・入力期限切れ等は500または接続切断となり、
失敗応答だけから保存の成否を推測しない。GETで状態を確認し、PENDINGかつ期限内なら同じIDへ再送、
INSPECTED/ABANDONEDならconfirm、CONFIRMEDならその登録を使用する。EXPIREDでは新しく予約する。
confirmは入力取得・再検査・再PUTをせず、保存先に到達できない場合も未存在として扱わない。

音源受信はRESTのentity parameterへ全体を渡さず、認可・受付確認後にworkerでHTTP入力を開く。
Quarkusの有界入力ストリームと既存の入力全体期限を使用し、未読入力を残す失敗は応答後に接続を閉じる。
Content-Lengthあり・chunkedの両方で最大256MiBを検査する。共通HTTP上限256MiBに加え、
`PrivateAudioBodyLimit`が音源PUT以外（機能無効時は全経路）を従来の10MiB以下に制限する。
本文を集約するフィルタをこの経路へ追加しない。フレームワーク更新時は大容量・chunked・送信停止の回帰を実行する。

## 検査・保存・確定と復旧の接続（B2b1）

`PrivateAudioIngestion` は内部で予約済みのIDを受け取り、PENDINGの照会→FLAC検査→検査結果の独立commit→
同じsnapshotの条件付き保存→HEADで全メタデータ照合→DB確定を接続する。検査結果のcommit応答前には保存しない。
期限や状態の競合で検査記録が拒否された呼出しも保存せず、snapshotを解放する。

DB操作は呼出元のVert.x event-loop contextへ戻し、入力の取得・検査・保存・closeはworkerで実行する。
同じインスタンスの受入数を1〜8件で制限し、混雑時は入力を取得せず拒否する。入力は受入後に一度だけ開き、
検査が終われば閉じる。snapshotは成功・失敗のどちらでも閉じる。入力closeに失敗した場合もsnapshotを片付ける。
購読取消は保存の成否を決めないため、内部の処理をそのまま完了させ、書込み中のsnapshotや受入枠を先に解放しない。

保存応答が失われてもHEADの実測値が検査記録と一致すれば確定する。未存在を確認できた場合だけ、
同じsnapshotで条件付きPUTを最大1〜3回まで試行する。HEADのアクセス拒否・取得障害・メタデータ不一致では
未存在と推測して再PUTしない。既存IDの競合や割込み後に未存在だった場合も再試行しない。自動削除は行わない。

`recover` はINSPECTEDの先行記録と保存実体を照合して確定する。入力の再取得・再検査・再PUTはしない。
検査前の予約期限を過ぎても復旧できるが、未存在・不一致・DB障害は失敗として残し、DBでの再確定は拒否する。
HTTPのconfirmは既にCONFIRMEDなら状態を返すだけで、再確定の遷移を実行しない。
DB確定後に応答や一時実体のcloseで失敗した場合は、照会で確定状態を確認する。

これはcoordinatorインスタンス内の同時実行制限。実行入口は一つのcoordinatorと共有一時領域を所有する。
管理者認可・既定無効化・Albumへの関連付けはC1、FLAC受信と確定/復旧APIはC2で接続している。

## 実行入口・入力期限・登録期限（B2b2b）

`PrivateAudioRuntime` は受入・明示復旧・定期照合を合わせて同時に1件だけ実行する。
取消後も内部処理が終了するまで枠を保持する。DB操作はVert.x event-loopで行い、
定期処理にも専用のduplicated contextを用意する。起動直後の照合は行わず、設定間隔で実行する。

入力は一時領域の容量予約後、最初のread時に取得する。入力のopen/read/closeを合わせた全体期限を設け、
別のdaemon thread 1本と待ち行列1件、8KiBの受渡しバッファ1件で読み進める。
期限切れ時はproducerへ割込みを要求するが、任意の入力I/Oを強制終了できるとはしない。
割込みを無視した入力はproducer枠を占有し続け、新たなthreadを増やさない。
producerはsnapshotに触れず、消費側が期限で戻って一時実体を解放する。
入力元のネットワーク接続にも有限のtimeoutが必要で、回復しない取得元は修復・再起動で復旧する。

定期照合はPENDING失効を最大10件、古いINSPECTEDのHEAD照合を最大10件、順に処理する。
INSPECTEDの対象時刻はDB時計で「元の予約期限 + retention」。一致する実体があれば確定し、
未存在のHEAD応答なら条件付きUPDATEでABANDONEDへ移す。障害・不一致では判断せず状態を維持し、
そのbatchを失敗として警告する。後続候補の進行を妨げる場合は保存先を調査・修復して再実行する。
これは受付終了であり、後からPUTが完了しないことの証明ではない。検査結果を残し、実体は自動削除しない。
遅延PUT後の通常確定は拒否するが、明示的な`recover`で全メタデータを照合して確定できる。
PENDING/EXPIRED/CONFIRMEDの復旧、再PUT、ID再利用は許さない。

設定のprefixは `abservice.private-audio`。実際の接続先・容量・運用値は非公開ABAffairsで管理する。

| 設定 | 既定値・条件 |
| --- | --- |
| `enabled` | `false`。文字列`true`だけが有効。それ以外は無効 |
| `bucket` | 有効時必須。公開画像バケットとは異なる専用バケット |
| `temporary-directory` | 有効時必須。POSIXの専有ローカル領域 |
| `temporary-bytes` | 512MiB。256MiB〜8GiB |
| `input-timeout` | `PT2M`。1ms〜5分 |
| `retention` | `PT24H`。1時間〜7日 |
| `maintenance-interval` | `PT15M`。1分〜24時間 |

無効時は専用S3クライアント・一時領域・timerを生成せず、全操作を拒否する。
有効時は専用の同期S3クライアントを所有し、既存の`quarkus.s3.aws.region`、
`quarkus.s3.endpoint-override`、`quarkus.s3.path-style-access`を使う。
資格情報はAWS標準provider chainで取得し、Quarkusの開発用static credentials設定は流用しない。
開発用S3互換環境でも、このクライアント用の資格情報を環境変数等で別途渡す。
接続5秒・socket30秒、S3操作全体2分で制限する。バケットやIAMは自動作成しない。

停止開始時にtimerと新規受入を止める。処理中ならcloseを失敗させて資源の所有を維持し、
処理完了後にcloseを再試行する。実行枠が空いてから入力executor・一時領域・S3クライアントを閉じる。
snapshot削除失敗等で一時領域を閉じられない場合も成功扱いにせず、領域を修復して再試行する。
終了処理が完了しないプロセスを停止した場合、次の起動で専有を取得して残骸清掃する。
通常の停止時間内に処理を完了できることと障害通知の受け入れはDで確認する。

V50は状態制約と期限検索indexの追加のみで、既存行を遷移・削除しない。
既定無効のまま既存機能を使える。ABANDONEDを実際に生成した後は、旧版がその状態を読めないため、
旧版へ戻す際の互換性を別途確認する。

## 一時領域の専有・総容量・起動時清掃（B2b2a）

`NativeFlacInspector` は `AudioTemporaryStore` を必須とし、任意のディレクトリへ直接保存しない。
実行環境はPOSIX権限とJavaのプロセス間ファイルロックを持つLinuxのローカルファイルシステムを前提とする。
専用ディレクトリをowner-onlyで作成し、既存の権限が広い場合やsymlink経由の場合は開始を拒否する。
同一領域を二重に開くと、同じJVM・別JVMのどちらでも拒否する。ロックは領域を閉じるまで保持し、
ロックファイル自体は削除しない。共有ネットワークファイルシステムでの排他は保証しない。
同一JVMの再openはファイルを開く前に拒否する。重複channelのcloseによって既存のOSロックが外れるケースも、
別JVMからの取得試験で防止を確認する。

検査前にその入力の `maxBytes` を予約し、検査完了後もsnapshotの削除まで保持する。
保存待ちや再試行中も予約を返さず、複数の検査器が同じstoreを使っても合計上限を超えない。
実サイズへ縮める最適化はせず、容量不足は入力読込前に拒否する。最大128実体までで、待ち行列は作らない。
この上限は検査snapshot用であり、HTTPアップロード受信領域・S3実体・OS全体の空き容量の保証ではない。

snapshotは0600で生成する。開いた読込streamが残っている間はsnapshotのcloseを拒否し、
snapshotが残っている間はstoreのcloseを拒否する。二重closeで予約量を増やさない。
削除失敗時も予約と領域の専有を保持し、修復後にcloseを再試行できる。
検査失敗時の削除にも失敗してsnapshotを呼出元へ返せなかった場合、予約を推測で返却しない。
領域を修復してプロセスを再起動し、起動時清掃を通す必要がある。

プロセスが強制終了した場合、次回のopenでロックを取得してから残骸を清掃する。
対象は専用の `flac-{UUID}.tmp` という名前の通常ファイルのみ。全対象を先に確認し、
未知のファイル・ディレクトリ・symlinkが一つでもあれば削除を始めない。1024件を超える残骸も拒否する。
再帰削除は行わず、DBや保存済みS3実体には触れない。旧形式のファイルや他用途の領域も自動削除しない。
稼働中に別プロセスがロックを無視してファイルを変更する利用は対象外とする。

実行入口が有効な場合にだけ単一storeを生成し、起動時清掃と寿命管理を行う。

## DBの登録状態と確定条件（B2a）

`PrivateAudioRegistrations` は、保存IDと検査結果をDBへ先行記録する。
各呼び出しは専用sessionの独立トランザクションでcommitしてから応答し、呼出元の後続rollbackで
保存前の検査記録が消えないようにする。音源検査・S3通信中のDBトランザクションは保持しない。

| 状態 | 保持する値・遷移 |
| --- | --- |
| PENDING | 内部発行ID・DB時計の作成時刻・検査前の予約期限。重複予約は更新しない |
| INSPECTED | 期限内のPENDINGへ検査結果を一度だけ記録。保存を開始する前にこのcommitが必要 |
| CONFIRMED | 保存先の実測値がDBの検査結果と全項目一致するときだけ遷移。再確定は拒否 |
| EXPIRED | 期限切れPENDINGだけを失効。検査結果は持たず、再利用しない |
| ABANDONED | 保持期間超過のINSPECTEDをHEAD未存在時に受付終了。検査結果は保持し、一致した実体の明示復旧だけを許可 |

状態を条件にした単一UPDATEで競合を判定し、先行する照会だけで排他したことにしない。
DB制約でも状態とメタデータの組合せ・初期FLACプロファイル・サイズ/時間上限を検査する。
検査結果の上書き・未検査の確定・照合不一致は成功にしない。状態遷移が成立しない場合はfalse、
DB障害やDB制約違反は失敗となり、呼出元が必要に応じて最新状態を読み直す。

`expirePending` は1〜1000件の上限付きで、ロック中の候補を飛ばして失効したIDを返す。
これは状態の失効だけであり、アップロード実体・DB行の削除は含まない。
INSPECTEDには応答喪失後の保存実体が存在する可能性があるため、この予約期限では失効させない。
期限後でも一致する実体を照合してCONFIRMEDへ復旧できる。

B2aの状態更新だけで保存実体の存在やフロー全体の復旧成功を保証しない。
この処理状態は公開Queryの入力ではなく、更新しても公開データ世代を進めない。

## 検査済み実体の非公開保存（B1）

`PrivateAudioStorage` は内部で払い出したUUIDと `InspectedAudio` を受け取り、検査したスナップショットを保存する。
任意のパス、元のファイル名、公開URL、再取得するアップロード元キーは受け取らない。
`S3PrivateAudioStorage` は専用バケットの `audio/verified/{UUID}.flac` へ単一のPUTを行い、
`If-None-Match: *` で既存キーへの書き込みを拒否する。同じ内容でも再書き込みは競合となる。
事前HEADだけで競合を防いだことにせず、条件をPUT自身へ載せる。
S3の412だけを使用済みIDの `PrivateAudioConflictException` とする。409は別操作との競合であり、
ID使用済みを確定できないため通常の `IOException` として照合・再試行へ戻す。
409や通信障害後も検査スナップショットは呼出元が保持し、B2で `find` による照合後、
未存在なら同じスナップショットを同じ不在条件付きで再試行できる。再試行回数/期限はB2で制限する。

実測byteLengthをContent-Lengthに、検査済みSHA-256をS3のチェックサムに指定する。
音源全体をメモリへ展開せず、SDKの再試行も同じスナップショットから新しいストリームを開く。
保存側が各ストリームを閉じ、スナップショット自体は呼び出し側が最後に閉じる。
sampleRate/channels/bitsPerSample/totalSamples、SHA-256、メタデータ形式の世代を実体と同じPUTで保持する。
外部のタグ、ファイル名、作品の表示情報は保存しない。

`find` はHEADから実体サイズを読み、S3チェックサムと保存メタデータのSHA-256を照合する。
404だけを未存在とし、403・通信失敗・欠損/不正メタデータ・チェックサム不一致は失敗にする。
保存応答が失われた場合は実体が残っている可能性があるため、自動削除や無条件の再PUTは行わない。
B2の復旧処理は事前にDBへ記録した検査結果と `find` の結果を照合する必要がある。
一致した保存実体があることと、DBで確定済みであること、端末へ配布する権限があることは別の状態として扱う。

保存ポートはブロッキングI/Oを行う。B2b1は検査器と共にイベントループ外へ配置し、同時処理数を制限する。
S3呼び出し全体の上限は2分とし、同期クライアントの寿命・接続/ソケットタイムアウトは構築側で設定する。
専用クライアントの構築と寿命管理は実行入口が担当する。バケット/IAMの作成・変更は行わない。

バケットの非公開性はキー名だけでは保証できない。接続時には公開画像バケット/CDNから分離した専用バケット、
Block Public Access、最小権限IAM、確定キーの条件付き書込強制を用意し、一般閲覧経路をDで検証する。
確定実体の削除や無条件PUTを許す権限があれば不変性を破れるため、アプリの通常経路には与えない。
pendingアップロードとverified実体の期限管理は分け、verified全体へ一律の期限削除を設定しない。

S3の根拠: [条件付き書き込み](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)、
[PutObjectのチェックサム](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html)。
S3互換MinIOでPUTの競合・チェックサム不一致・匿名取得拒否を検査するが、本番IAM/CDNの受け入れ証跡はDに残す。
管理APIの予約・照会・関連付けはC1、受信/確定/復旧はC2で接続済み。実環境の権限と操作手順の受け入れはDに残る。

## 受入条件

- native FLAC（先頭が `fLaC`）。Oggコンテナや、拡張子/Content-Typeの申告による判定は受け入れない。
- STREAMINFOが先頭にあり長さ34バイト。サンプル数とPCMのMD5が記録されていること。
- 初期プロファイルはモノ/ステレオ、16/24bit、8〜96kHz。範囲外は明示的に拒否し、変換しない。
- 各フレームのsampleRate・channels・bit depthはSTREAMINFOと一致すること。途中の量子化変更も拒否する。
  analysisにbit depthが含まれないため、同じ検査実体のframe offsetからヘッダを読み、コード0はSTREAMINFOを継承する。
- 初期上限は **256MiB / 2時間**。画像上限・音源の平均サイズ・端末の使用可能容量とは独立する。
- 全体デコード検査でフレーム破損、CRC・MD5不一致、途中切断等を拒否する。
  実フレームの連続範囲・サンプル数も照合し、末尾データやSTREAMINFOの申告違いを拒否する。
- 実測byteLength、ファイル全体のSHA-256、sampleRate、channels、bitsPerSample、totalSamplesを返す。
  durationMillisはtotalSamples/sampleRateからミリ秒単位で切り上げる。MD5はFLAC内部のPCM照合、
  SHA-256はファイル実体の識別に用い、役割を混同しない。

初期プロファイルは試聴端末での再生保証ではない。長尺・実容量・性能は #478 の受け入れで別に検証する。
クロスフェードと将来の曲音源で検査器を分けない。種別・Album/Track IDは登録側の責務とする。

## 検査済み実体の所有権

`FlacInspector.inspect` は入力を専用の一時ファイルへストリーム保存する。メモリへ全体を展開しない。
上限超過は保存中に拒否し、一時ファイルは成功時以外すべて削除する。
成功すると `InspectedAudio` がそのファイルを所有し、パスを公開せず読み取りストリームだけを提供する。
確定処理はこのストリームを保存する。検査後にアップロード元のキーを再取得して保存してはならない。

呼び出し側は `InspectedAudio` と開いたストリームをtry-with-resourcesで閉じる。
入力ストリームは呼び出し側の所有であり、実行入口では期限付き入力が取得元のcloseまで所有する。
専用のアクセス制限された一時領域を渡し、イベントループの外で実行する。
検査器は同一インスタンスで同時に1件までを受け入れ、待ち行列を無制限に作らない。

全体デコードには `flac --test --silent --warnings-as-errors` を引数配列で起動し、
続いて `--analyze --stdout` のフレーム解析を逐次集計する。testだけでは一部のサンプル数の申告違いと
末尾データを拒否しないため、実フレームの番号・offset/bit長・サンプル数・rate/channelsを照合する。
解析出力の形式が変わって照合できない場合も拒否する。CLI更新時は実コマンドの統合テストで互換性を確認する。
シェル解釈を挟まない。PCM出力や解析出力をファイルへ保存せず、タグや元のファイル名をログへ載せない。
2回の起動を合わせた検査時間の既定上限は2分。時間切れ・割り込み時はプロセス終了を待ってから片付ける。
入力不合格（`InvalidFlacException`）と、取得障害・検査器不在・混雑・時間切れ（`IOException`）を区別する。

プロセス強制終了・ホスト再起動時にはfinallyを実行できないため、専有領域の次回openで残骸を清掃する。
HTTPで受信する未確定実体も同じ専用一時領域・容量予約・入力全体期限の管理下に置く。
検査器の一時領域上限だけで、全リクエストや確定待ちS3音源の総使用量まで制限できるとはしない。

## ランタイムと検証

backendイメージはAmazon Linuxの `flac` パッケージを導入する。
ローカルで実デコードの統合検査を行う場合も `flac` をPATHへ用意する。
CIは同じ統合テストで実コマンドを起動し、欠如をskipや成功にしない。

```sh
backend/gradlew -p backend integrationTest --tests '*NativeFlacInspectorIntegrationTest'
```

テスト内で合成PCMからFLACを生成し、16/24bit、mono/stereo、ヘッダ偽装・破損・切詰め、
サイズ/時間上限、デコード停止、取得失敗、一時実体の解放を確認する。実作品の音源は含めない。
`PrivateAudioRuntimeIntegrationTest`では既定無効、実FLACからDB確定、保持期限の照合、
遅延保存の明示復旧、稼働中の停止を確認する。`DeadlineAudioInputTest`は割込みを無視する取得元も検査する。
`PrivateAudioUploadRestIntegrationTest`は合成FLACをHTTP受信から実MinIOの非公開保存まで通し、
10MiB超の入力、chunked、期限切れ・不正形式、明示復旧、HTTP上限、送信停止後の資源回復を検査する。
同じ試験で、SQLによる確定状態の代用をせずに予約→受信→検査/保存→確定→Album関連付け→照会まで通す。
公開Albumの応答・公開データ世代が変わらず、音源が画像バケットへ保存されず、匿名取得できないことも照合する。
復旧の障害注入では、別の正常なFLACとその保存メタデータへ実体を差し替え、確定・再PUTを行わないことを確認する。
音源機能を有効にしたまま画像の署名付きPUT→確定→匿名取得を通し、画像用上限とFLAC形式の拒否を維持する。

保存アダプタの統合テストは開発/CIのMinIOを使う。
`S3PrivateAudioStorageIntegrationTest` は毎回専用の一時バケットを作成し、試験後に削除する。
検査器の代役の合成バイト列で、大きな実体の往復、上書き・並行PUT・SHA-256不一致・匿名取得拒否を確認する。
これは保存境界の検査であり、登録から照会までの結合試験を代替しない。

検査は [XiphのFLAC CLI](https://www.xiph.org/flac/documentation_tools_flac.html) の全体検査を利用する。
CLIは別プロセスで利用し、ライブラリをアプリへ静的リンクしない。
FLAC CLIのGPLとlibFLACのBSDライセンスは配布パッケージに保持する。
仕様参照: [RFC 9639](https://www.rfc-editor.org/rfc/rfc9639.html)。

## 結合受け入れと有効化の条件（D）

ローカル/CIの結合検査は次のコマンドで再現する。実DB・MinIO・FLAC CLIが必要で、入力は合成データだけを使う。

```sh
backend/gradlew -p backend integrationTest \
  --tests '*PrivateAudioUploadRestIntegrationTest' \
  --tests '*AssetUploadRestIntegrationTest'
```

音源HTTP試験は専用の `QuarkusTestProfile` で起動し、通常試験からのリソース切替時に
Reactiveセッション状態を引き継がない。単独実行だけでは起動切替を検証できないため、
変更後は `backend/gradlew -p backend check integrationTest --rerun` で全件との共存も確認する。

| 確認する境界 | 自動検査 | 実環境に残る条件 |
| --- | --- | --- |
| 登録から作品選択 | HTTPで予約→実FLAC受信→確定→Album関連付け、未確定の関連付け拒否、Album削除後も音源保持 | 実作品のクロスフェードで同じ操作を実施し、実測容量・SHA-256を照合 |
| 非公開と画像の分離 | 音源の匿名取得拒否、公開APIに経路なし、公開Album/世代不変、画像バケットへ音源が入らない、画像の公開往復 | 専用バケット・Block Public Access・IAM・CDN/OACからの隔離、公開ドメインからの拒否 |
| 不正入力と中断 | 不正形式/期限/再送の拒否、HTTP容量制限、送信停止後の受付再開、検査器の破損/切詰め・一時領域回収 | 実配信経路の容量・期限・切断、ホストのディスク容量と権限、プロセス再起動後の回収 |
| 確定復旧 | INSPECTED/ABANDONEDの実体照合、未存在/差替えの拒否、確定済みconfirmの冪等応答 | 保存先への認可失敗・通信障害・応答喪失からの復旧、停止時間内の完了 |

この表は検査の対応関係であり、CI成功を実環境受け入れ済みとはしない。検査後の差替え試験で行う
ストレージへの直接書込みやDB状態変更は隔離したテストの障害注入専用で、運用手順として実施しない。
認証した端末への取得は #475 の別契約であり、管理者の登録成功から端末配布の成功を推定しない。

有効化前に、以下を配布候補のcommitに対して確認する。実値・操作結果・音源の証跡はABAffairsへ記録する。

1. 専用バケットと最小限の保存/照合権限を用意し、公開画像の配信対象に含めない。アプリ用資格情報で
   保存・HEAD照合を通し、匿名アクセスと公開CDN経路の拒否を別に検査する。
2. 専用一時領域の所有者・権限・容量を確認し、enabled/bucket/temporary-directoryを配布設定へ接続する。
   cohostの`deploy.py`は任意の`private_audio`設定で配線し、既定無効を維持する。
   専用領域は事前作成し、UID/GID 1000:1000・mode 0700・空き容量を確認する。
3. 利用するHTTP経路の上限・入力バッファ・応答待ち時間を確認する。cohostの`origin.py`には
   `--tls --private-audio`で管理音源contentのPUTだけに256MiB・入力buffering無効・応答待ち300秒を設定する。
   他のAPIは1MiB/60秒を維持する。CDN側は`backend_response_timeout`（既定30秒、明示で最大60秒）を別途検査し、
   最も短い待ち時間が経路の上限となる。実サイズで測定し、504/応答喪失後は状態照会・確定復旧を行う。
4. 予約→送信→状態照会→Album関連付けを実行し、送信前のファイルと登録応答の容量・SHA-256を照合する。
   関連付けの世代はGETで取得し、409では最新状態を読んでから判断する。元の作品情報・公開画像も確認する。
5. 送信中断・保存応答喪失・停止/再開を検証する。PENDINGは期限内のみ再送、INSPECTED/ABANDONEDは
   confirm、CONFIRMEDは既存登録を使う。障害時に音源やDB記録を手作業で削除して再送しない。
6. 無効化で管理音源APIが404となり、一般の作品表示・画像・管理操作が動くことを確認する。
   関連付け解除や無効化を、登録音源の削除と同一視しない。

## 後続の #474 / #475 へ渡す条件

- 管理者認可と未完成機能の既定無効化をAPI入口で検査する。
- pending/確定済みを分離し、確定済みキーを上書きしない。競合と再確定を拒否する。
- 検査済み実体・メタデータを対応付け、片方だけの成功や中断から復旧可能にする。
- 公開画像のprefix/CDN/OAC/APIに音源を混ぜず、一般閲覧から取得できないことを試験する。
- C1のクロスフェード関連付けを実受信からの結合試験へ接続する。曲音源は別の参照枠で拡張する。
- 管理APIの契約・操作手順・停止/清掃・期限削除・保存後の不変性まで検証して #474 を完了する。
