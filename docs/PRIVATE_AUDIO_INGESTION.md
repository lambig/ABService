# 非公開FLACの受入検査（#474）

## 現在の実装境界

この段階で実装するのは、非公開音源の検査器、検査済み実体を渡す契約、専用の保存アダプタ。
管理API、DBの状態と保存先を結ぶ確定フロー、Album/再生項目との関連付けは #474 の後続作業であり、
認証した試聴端末への配布は #475 が担当する。公開画像のアップロードAPIには接続しない。
新しいAPIや取得経路は存在せず、保存アダプタもCDIへ接続していない。この基盤だけで #474 を完了とはしない。

## 検査済み実体の非公開保存（B1）

`PrivateAudioStorage` は内部で払い出したUUIDと `InspectedAudio` を受け取り、検査したスナップショットを保存する。
任意のパス、元のファイル名、公開URL、再取得するアップロード元キーは受け取らない。
`S3PrivateAudioStorage` は専用バケットの `audio/verified/{UUID}.flac` へ単一のPUTを行い、
`If-None-Match: *` で既存キーへの書き込みを拒否する。同じ内容でも再書き込みは競合となる。
事前HEADだけで競合を防いだことにせず、条件をPUT自身へ載せる。

実測byteLengthをContent-Lengthに、検査済みSHA-256をS3のチェックサムに指定する。
音源全体をメモリへ展開せず、SDKの再試行も同じスナップショットから新しいストリームを開く。
保存側が各ストリームを閉じ、スナップショット自体は呼び出し側が最後に閉じる。
sampleRate/channels/bitsPerSample/totalSamples、SHA-256、メタデータ形式の世代を実体と同じPUTで保持する。
外部のタグ、ファイル名、作品の表示情報は保存しない。

`find` はHEADから実体サイズを読み、S3チェックサムと保存メタデータのSHA-256を照合する。
404だけを未存在とし、403・通信失敗・欠損/不正メタデータ・チェックサム不一致は失敗にする。
保存応答が失われた場合は実体が残っている可能性があるため、自動削除や無条件の再PUTは行わない。
B2の復旧処理は事前にDBへ記録した検査結果と `find` の結果を照合する必要がある。
一致した保存実体があることと、DBで確定済みであること、端末へ配布する権限があることは別の状態として扱う。

保存ポートはブロッキングI/Oを行う。B2で検査器と共にイベントループ外へ配置し、同時処理数を制限する。
S3呼び出し全体の上限は2分とし、同期クライアントの寿命・接続/ソケットタイムアウトは構築側で設定する。
この段階では本番クライアントの構築・設定追加、バケット/IAMの作成・変更を行わない。

バケットの非公開性はキー名だけでは保証できない。接続時には公開画像バケット/CDNから分離した専用バケット、
Block Public Access、最小権限IAM、確定キーの条件付き書込強制を用意し、一般閲覧経路をDで検証する。
確定実体の削除や無条件PUTを許す権限があれば不変性を破れるため、アプリの通常経路には与えない。
pendingアップロードとverified実体の期限管理は分け、verified全体へ一律の期限削除を設定しない。

S3の根拠: [条件付き書き込み](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)、
[PutObjectのチェックサム](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html)。
S3互換MinIOでPUTの競合・チェックサム不一致・匿名取得拒否を検査するが、本番IAM/CDNの受け入れ証跡はDに残す。
DB状態・中断復旧・pendingの期限削除・一時領域清掃/総量制限はB2、管理API/認可はCで接続する。

## 受入条件

- native FLAC（先頭が `fLaC`）。Oggコンテナや、拡張子/Content-Typeの申告による判定は受け入れない。
- STREAMINFOが先頭にあり長さ34バイト。サンプル数とPCMのMD5が記録されていること。
- 初期プロファイルはモノ/ステレオ、16/24bit、8〜96kHz。範囲外は明示的に拒否し、変換しない。
- 各フレームのsampleRate・channels・bit depthはSTREAMINFOと一致すること。途中の量子化変更も拒否する。
  analysisにbit depthが含まれないため、同じ検査実体のframe offsetからヘッダを読み、コード0はSTREAMINFOを継承する。
- 初期上限は **256MiB / 2時間**。画像上限・音源の平均サイズ・端末の使用可能容量とは独立する。
- 全体デコード検査でフレーム破損、CRC・MD5不一致、途中切断等を拒否する。
  実フレームの連続範囲・サンプル数も照合し、末尾データやSTREAMINFOの申告違いを拒否する。
- 実測byteLength、ファイル全体のSHA-256、sampleRate、channels、bitsPerSample、totalSamplesを返す。
  durationMillisはtotalSamples/sampleRateからミリ秒単位で切り上げる。MD5はFLAC内部のPCM照合、
  SHA-256はファイル実体の識別に用い、役割を混同しない。

初期プロファイルは試聴端末での再生保証ではない。長尺・実容量・性能は #478 の受け入れで別に検証する。
クロスフェードと将来の曲音源で検査器を分けない。種別・Album/Track IDは登録側の責務とする。

## 検査済み実体の所有権

`FlacInspector.inspect` は入力を専用の一時ファイルへストリーム保存する。メモリへ全体を展開しない。
上限超過は保存中に拒否し、一時ファイルは成功時以外すべて削除する。
成功すると `InspectedAudio` がそのファイルを所有し、パスを公開せず読み取りストリームだけを提供する。
確定処理はこのストリームを保存する。検査後にアップロード元のキーを再取得して保存してはならない。

呼び出し側は `InspectedAudio` と開いたストリームをtry-with-resourcesで閉じる。
入力ストリームは呼び出し側の所有であり、読込タイムアウト・切断/キャンセルも取得側で管理する。
専用のアクセス制限された一時領域を渡し、イベントループの外で実行する。
検査器は同一インスタンスで同時に1件までを受け入れ、待ち行列を無制限に作らない。

全体デコードには `flac --test --silent --warnings-as-errors` を引数配列で起動し、
続いて `--analyze --stdout` のフレーム解析を逐次集計する。testだけでは一部のサンプル数の申告違いと
末尾データを拒否しないため、実フレームの番号・offset/bit長・サンプル数・rate/channelsを照合する。
解析出力の形式が変わって照合できない場合も拒否する。CLI更新時は実コマンドの統合テストで互換性を確認する。
シェル解釈を挟まない。PCM出力や解析出力をファイルへ保存せず、タグや元のファイル名をログへ載せない。
2回の起動を合わせた検査時間の既定上限は2分。時間切れ・割り込み時はプロセス終了を待ってから片付ける。
入力不合格（`InvalidFlacException`）と、取得障害・検査器不在・混雑・時間切れ（`IOException`）を区別する。

プロセス強制終了・ホスト再起動時にはfinallyを実行できない。後続のAPI/保存実装では、一時領域の起動時清掃、
総容量の制限、成功後のclose、未確定アップロードの期限削除を接続する。検査器の1ファイル上限だけで、
全リクエストや確定待ち音源の総使用量まで制限できるとはしない。

## ランタイムと検証

backendイメージはAmazon Linuxの `flac` パッケージを導入する。
ローカルで実デコードの統合検査を行う場合も `flac` をPATHへ用意する。
CIは同じ統合テストで実コマンドを起動し、欠如をskipや成功にしない。

```sh
backend/gradlew -p backend integrationTest --tests '*NativeFlacInspectorIntegrationTest'
```

テスト内で合成PCMからFLACを生成し、16/24bit、mono/stereo、ヘッダ偽装・破損・切詰め、
サイズ/時間上限、デコード停止、取得失敗、一時実体の解放を確認する。実作品の音源は含めない。

保存アダプタの統合テストは開発/CIのMinIOを使う。
`S3PrivateAudioStorageIntegrationTest` は毎回専用の一時バケットを作成し、試験後に削除する。
検査器の代役の合成バイト列で、大きな実体の往復、上書き・並行PUT・SHA-256不一致・匿名取得拒否を確認する。
これは保存境界の検査であり、登録から照会までの結合試験を代替しない。

検査は [XiphのFLAC CLI](https://www.xiph.org/flac/documentation_tools_flac.html) の全体検査を利用する。
CLIは別プロセスで利用し、ライブラリをアプリへ静的リンクしない。
FLAC CLIのGPLとlibFLACのBSDライセンスは配布パッケージに保持する。
仕様参照: [RFC 9639](https://www.rfc-editor.org/rfc/rfc9639.html)。

## 後続の #474 / #475 へ渡す条件

- 管理者認可と未完成機能の既定無効化をAPI入口で検査する。
- pending/確定済みを分離し、確定済みキーを上書きしない。競合と再確定を拒否する。
- 検査済み実体・メタデータを対応付け、片方だけの成功や中断から復旧可能にする。
- 公開画像のprefix/CDN/OAC/APIに音源を混ぜず、一般閲覧から取得できないことを試験する。
- Albumへのクロスフェード関連付けと参照先・種別の検査を実装する。
- 管理APIの契約・操作手順・停止/清掃・期限削除・保存後の不変性まで検証して #474 を完了する。
